# eng-decision · 决策记录

决策记录解决一个问题：**半年后有人问「为什么这么定」，有没有答案。**

> 模板：`../../templates/decision.md.tpl`。若宿主提供插件根路径变量，优先使用。

---

## 一、什么时候该独立成文

**判据：有取舍代价的决策才独立成文。** 没有代价的，只是执行细节。

| 独立成文 | 只在索引里记一行 |
|---|---|
| 「放弃方案 A，代价是 X」 | 「用 Python 而非 TypeScript」——若没有代价，一行足够 |
| 「接受某平台限制，换取 Y」 | 「字段名用 snake_case」 |
| 「推翻三个月前的结论」 | 「增加一个工具」 |
| 「决定不做某功能」 | — |

> 独立成文过多会让目录变成噪声；过少会让关键决策无处可查。**用「有没有代价」这条线切。**

---

## 二、命名与位置

```
docs/decisions/D<N>-<slug>.md
```

- `N` 是顺序号，**不补零**（`D2`、`D12`）
- `slug` 用短横线连接的小写英文或拼音，长度控制在 30 字符内
- 编号冲突时顺延，**禁止复用**

### 两种编号要分清

| 形式 | 用途 | 例子 |
|---|---|---|
| `D-1`、`D-2`… | **索引条目**（ROADMAP 决策表里的短决策） | `D-3` = 单进程 + 按用户配后端类型 |
| `D2`、`D3`… | **独立成文的决策记录文件** | `D2-entry-and-scope.md` |

> 这两套混用是最常见的追溯断裂来源。规则：**文件用 `D<N>`，表格条目用 `D-<N>`**，并在 ROADMAP 里明确说明。
> 架构文档另有编号（如 `A1`），不要也用 `D`——否则 `D1` 到底是架构还是决策就说不清。

## 三、必含六段

```markdown
## 一、背景
<触发这次决策的场景与约束>

## 二、选项
<列出的候选，含被否掉的>

## 三、决定
<最终选择，一句话>

## 四、理由
<为什么选它，逐条>

## 五、放弃的代价
<选了它要付出什么——这一段最容易被跳过，也最重要>

## 六、何时可能推翻
<什么条件下应该重新评估>
```

### 为什么「放弃的代价」必须写

不写代价的决策记录 = 宣传材料。半年后有人质疑，你只能重新论证一遍。

写了代价，等于提前承认「这是个已知的妥协」——这正是好决策的标志。

### 为什么「何时可能推翻」必须写

决策有保质期。写下推翻条件，等于给未来的自己留了一个触发器：

```
| 条件 | 推翻什么 |
|---|---|
| 上游把 X 改成收费 | 换 Y |
| 用户量超过 N | 拆进程 |
| 平台取消该能力 | 回退到 Z |
```

---

## 四、推翻时怎么处理

**不删旧文档。** 三步：

1. 旧文档 frontmatter 改 `status: superseded`
2. 在旧文档顶部加一行指向新决策：`> 已被 [[D<N>-xxx]] 取代。`
3. 新文档的「背景」里写明「原方案的问题是什么」

同时在 ROADMAP 的决策索引里，把旧条目标为 `🔁 已取代`，不要直接删除——**删除会让历史的双链全部悬空**。

---

## 五、反模式

| 反模式 | 后果 |
|---|---|
| 决策只存在于对话里 | 上下文一压缩就没了，新人无法追溯 |
| 只写结论不写代价 | 变成宣传；被质疑时无法自证 |
| 推翻时静默改文档 | 历史双链断裂，无法解释「为什么变了」 |
| 把愿景当决策 | 「要做最好的助理」不是决策，是口号 |
| 决策记录里放实施细节 | 实施细节属于架构文档，混放会两边都过期 |
| 编号复用 | 两条不同决策共用一个号，追溯彻底失效 |

## 六、与其它文档的衔接

| 文档 | 关系 |
|---|---|
| `ROADMAP.md` | 决策索引（唯一权威的编号清单）；独立成文的决策在此标注文件链接 |
| `docs/architecture/` | 决策的**结论**落到架构规格里；决策文档记录**过程** |
| `docs/research/` | 决策的**证据**来自调研；调研报告不写结论，结论写进决策记录 |
| `CHANGELOG.md` | 影响用户可感知行为时，记一条「变更」并引用决策编号 |

**链式关系**：调研（证据）→ 决策（取舍）→ 架构（规格）→ 里程碑（交付）。缺任何一环，追溯都会断。

## 七、自检

```
[ ] 有「放弃的代价」且不是「几乎没有代价」
[ ] 有「何时可能推翻」且条件可观测
[ ] 编号未与既有决策冲突
[ ] 若推翻了旧决策，旧文档已标 superseded 并加指针
[ ] ROADMAP 决策索引已同步（含状态标记）
[ ] 没有把实施细节写进来
```
