# eng-bootstrap · 工程骨架

一次性解决三件事：**这个项目不做什么**、**版本号怎么涨**、**什么算完工**。

> 模板：`../../templates/`（`AGENTS` / `ROADMAP` / `CHANGELOG` / `README` / `gitignore`）。本技能目录的上两级即模板根；宿主提供插件根路径变量（如 `${CLAUDE_PLUGIN_ROOT}`）时优先使用。

---

## 一、先选入口（三种，不是一种）

| 入口 | 适用 | 第一步 |
|---|---|---|
| **A 冷启动** | 全新项目，范围已清楚 | §三 四项必问 → §四 生成骨架 |
| **B 调研先行** | 范围不确定 / 技术可行性未知 | §二 建最小目录 → 跑调研 → 回来定稿 |
| **C 补建/迁移** | 已有文档，但散乱或不合规 | §五 盘点 → 映射 → 冻结 |

**判据**：答不上「明确不做什么」和「技术栈约束」→ 走 B，不要走 A。

---

## 二、入口 B · 最小目录

骨架定稿前，只建这些：

```
<project>/
├── docs/research/     # 调研报告（NN-slug，从 01 起）
├── docs/decisions/    # 取舍记录
└── _refs/             # 外部参考源码快照（gitignore）
```

**不要提前写 AGENTS.md**——「明确不做的事」和「技术栈约束」正是调研的产出，先写死就要返工。调研跑完（通常 3–9 轮，见 `eng-research`）后，回入口 A 定稿。

---

## 三、入口 A · 四项必问（不可代填）

| # | 必问 | 为什么不能猜 |
|---|---|---|
| 1 | **能力边界**：明确**不做**什么 | 「不做什么」是唯一有效的防蔓延手段 |
| 2 | **规模画像**：单人/小团队；用户量级；是否对外 | 决定要不要多进程、权限体系、计费 |
| 3 | **版本节奏**：里程碑几个；`y` 位绑里程碑还是绑发布批次 | 决定 ROADMAP 结构，事后改成本极高 |
| 4 | **覆盖率目标**：三档各多少 | 决定测试分层粒度 |

用户只说「想搭个骨架」时，用下方默认值提案，但**必须让用户逐项确认**：

```
能力边界：由用户填（不可代填）
规模：单进程 + 单库；不做分布式、不做计费
版本节奏：y 位绑里程碑（M01 → 0.1.z）
覆盖率：里程碑 80% / 全局集成 75% / 核心纯函数 100%
```

## 四、入口 A · 生成骨架

### 4.1 目录结构

```
<project>/
├── README.md          # 定位、从哪读起、设计要点速览
├── AGENTS.md          # 开发规约（强制，设计公理的唯一权威）
├── ROADMAP.md         # 里程碑 × 版本号（唯一权威）
├── CHANGELOG.md       # 变更记录
├── .gitignore         # 见 templates/gitignore.tpl
├── docs/
│   ├── architecture/  # A<N>-slug
│   ├── research/      # NN-slug（从 01 起）
│   ├── milestones/    # M<NN>-slug
│   ├── decisions/     # D<N>-slug
│   └── reviews/       # R<N>-slug（审查记录）
└── _refs/             # 外部参考源码快照（gitignore）
```

**五个子目录各承接一类产出，混放会让检索失效。** 小项目（≤3 里程碑）可暂不建 `architecture/`；一旦出现跨模块约束就必须建。各目录的索引文件用 `templates/research-index.md.tpl` / `milestones-index.md.tpl` / `architecture-index.md.tpl`。

### 4.2 五个顶层文件的职责边界

| 文件 | 只写什么 | **不写**什么 |
|---|---|---|
| `README.md` | 定位、目录导航、从哪读起 | 设计公理（在 AGENTS）、里程碑清单 |
| `AGENTS.md` | 栈约束、版本规则、门禁、文档规范、设计公理、**明确不做的事** | 进度、计划 |
| `ROADMAP.md` | 里程碑 ↔ 版本号映射（**唯一权威**）、决策索引 | 设计理由、任务细节 |
| `CHANGELOG.md` | 用户可感知的变化 | 重构、格式化、注释、测试补充 |
| `docs/*` | 各自领域的长文 | 顶层文件已有的内容 |

**判据**：同一句话只能放一个地方——放「最容易被查阅」的那个，其余双链指过去。

### 4.3 版本号绑定（x.y.z）

```
x — 只在「对已有用户数据/接口不兼容」时递增；x=1 表示首个对外交付版
y — 与里程碑强绑定：M01 → 0.1.z，M02 → 0.2.z
z — 里程碑内小迭代：每次增量交付递增
```

三条铁律：① 里程碑验收通过打该里程碑的 `.0`；② 里程碑内补充用 `.1`、`.2`…，**不得**动下一个 `y`；③ 跨里程碑必须同步 ROADMAP 与 CHANGELOG。

### 4.4 验收门禁（写进 AGENTS）

必须**可判真伪**，并按阶段分档：

```
[ ] 前置调研完成且落盘
[ ] 若已进入编码阶段：覆盖率 ≥ <项目设定值>
[ ] 无新增未记录的技术债
[ ] ROADMAP 与 CHANGELOG 已同步
[ ] 版本号已按规则更新
[ ] 用户已确认
```

❌ 不写「覆盖率达标」「质量良好」——换个人无法判定。

## 五、入口 C · 补建/迁移

已有文档的项目**不能直接套入口 A**——会撞号、会残留旧表。

### 5.1 先盘点，不要先动手

```
1. 跑一次 eng-audit 机械项：现有编号、双链、frontmatter 现状
2. 列「旧文件 → 四目录」映射表，逐行确认
3. 编号占用预检：确定每类新号从哪个开始（最容易出错的一步）
```

第 3 步可选脚本加速：`scripts/number-inventory.sh [docs目录]`——输出各编号空间的占用、断号与下一个可用号；无脚本环境用 `grep -rE '(D|A|R)[0-9]+-|M[0-9]{2}-|^[0-9]{2}-' docs/` 人工盘点。

### 5.2 迁移顺序

```
1. 建新目录，移动而非复制（复制会留下两份权威）
2. 按映射表归类：架构 / 调研 / 里程碑 / 决策 / 审查
3. 统一 frontmatter（补 title/type/status/updated）
4. 重编号：只改需要改的，改完全文搜索旧号
5. 跑 eng-audit 机械项回归
6. 最后才补 AGENTS / ROADMAP 里的索引
```

### 5.3 三个已知陷阱

| 陷阱 | 后果 |
|---|---|
| 不预检编号就分配新号 | 与旧文档撞号，后续编号全链失效 |
| 新旧两套编号并存 | 「D1 是架构还是决策」无法回答 |
| 复制而非移动 | 两份文档都声称权威，三个月后没人知道信哪个 |

## 六、反模式

| 反模式 | 后果 |
|---|---|
| 能力边界靠猜 | 返工落在 ROADMAP/AGENTS 全部下游 |
| 先写代码后补规约 | 规约补不上，或补成事后合理化 |
| 里程碑按「功能模块」切 | 每个都无法独立验收 |
| AGENTS 写成愿望清单 | 没有约束力 |
| 目录里塞 `misc/` `notes/` `tmp/` | 半年后无人知道哪个是权威 |
| 版本号随手涨 | 版本号失去信息量 |
| 不做 `.gitignore` 就 `git add .` | 几 GB 参考源码进库 |
| 设计公理同时写在 README 和 AGENTS | 两处必然漂移 |
| 存量项目直接套冷启动 | 撞号 + 旧表残留 |

---

## 七、自检

```
[ ] 已明确走哪个入口（A 冷启动 / B 调研先行 / C 补建迁移）
[ ] 五项顶层文件齐备，职责无重叠（公理只在 AGENTS）
[ ] 五个 docs 子目录齐备（小项目可暂缺 architecture/，需说明理由）
[ ] .gitignore 已排除参考快照与大文件
[ ] AGENTS 含「明确不做的事」且每条带原因
[ ] AGENTS 含可判真伪、按阶段分档的验收门禁
[ ] 版本号规则含「y 位绑里程碑」与三条铁律
[ ] ROADMAP 声明自己是「版本号唯一权威」
[ ] README 给出「从哪读起」导航，未重复 AGENTS 公理
[ ] 若是入口 C：编号占用已预检，旧文档已移动（非复制），旧编号无残留
```

**任何一项没做到，不要交付**；改为输出「卡在哪 + 需要谁做什么」。

## 八、下一步

- 骨架完成 → `eng-milestone` 拆第一个里程碑
- 「能力边界」其实还没想清 → 回入口 B，先跑 `eng-research`
- 存量项目迁移完 → `eng-audit` 阶段一
- 不知道怎么收尾 / 发版 / 交接 → `eng-system`
