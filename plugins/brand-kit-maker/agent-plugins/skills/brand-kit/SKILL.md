# 制作品牌套件

以本文件所在目录的上两级为插件根目录。先读 [需求清单](references/brief.md) 和 [定稿与交付](references/delivery.md)。可按需参考可复现的 [Ravn Kolchis 示例](../../examples/ravn-kolchis/README.md)。

## 1. 理清原始需求

从用户已有描述和素材中填需求清单。标记会影响交付但尚不明确的项目，集中询问。明确品牌名、用处、目标受众、是否带副标题、视觉意象和限制、已有底稿、深浅背景及目标文件。已有正式设计时，从用户要改的环节开始，并复用已确认的决定。

## 2. 讨论设计并确认每个方面

- **Logo**：从意象和视觉限制推导少量候选方向，每个说明轮廓、层次和小图表现。用户选方向后，优先在选定底稿上调整。需要原创新图时，使用当前环境可用的图像工具输出候选并展示。需要抠图时，优先真透明底稿，其次是与主体颜色不重叠的纯色底。确认具体文件，并看浅底、深底和 16、32、48 px 的表现。
- **配色**：给出能和定稿图形配合的方案。说明主色、辅助色和点缀色的角色，预览两套背景上的图形、名称与副标题。确认各用途的 HEX/RGB。渐变用代表色记录。在真实背景上对比文案的清晰程度。
- **文案**：讨论名称大小写、空格、符号、准确拼写、副标题或铭文的原文和取舍。用户提供词源、出处或译文时，保留原文并标明语境。分别确认完整文本、是否保留副标题、名称能否断为两行及明确断行位置。
- **字体和组合**：用同一图形与实际文案展示字体、字重、字距和图文间距。字体选择参考字形、所需字符、授权和可获取的源文件。名称和副标题可选择常规或斜体字形。展示横排、竖排、适用的单行或双行，以及浅底和深底。检查副标题没有压过品牌名称。
- **最终样张**：将以上结论填入品牌配置，先导出预览。向用户展示样张和将要生成的文件矩阵。逐项记录用户实际认可的内容。用户可以一次确认多个方面，也可以逐项确认。发现印象或对比不足时，回到相应环节，并复查受影响的布局。

## 3. 按定稿导出

1. 复制 [配置模板](../../templates/brand.json)，填入准确素材、文案、字体、色板和组合方式。只有实际获得确认的项目才把对应 `approval` 设为 `true`。
2. 在 Windows PowerShell 7 中运行 [导出脚本](../../scripts/export-brand-kit.ps1)，传入配置文件和一个新输出目录。评审阶段加 `-PreviewOnly`，只保留预览。最终导出需要五项确认，包括用户认可样张。将确认的决定填入 [讨论记录](../../templates/discussion.md)，最终导出用 `-DiscussionPath` 将它收入交付目录。
3. 核对源图归档、透明母图、PNG 尺寸、两套 ICO、独立字图和组合图。检查两种底色、最小尺寸、文案拼写、字形与间距。链接到保留的定稿与品牌总 README。
4. 根据用户反馈更新配置与样张。若改动已确认的项目，清除对应确认及 `proof`，重新查看受影响的样张。将正式输出写入新目录，避免覆盖已确认版本。文档中的清单应按实际产物生成。

默认授权字体为随附的 Cormorant Garamond。用户有其他字体要求时，在配置中提供字体文件和授权文本。图像创作与评审由会话完成，导出脚本负责从确认后的位图与文字生成文件。
