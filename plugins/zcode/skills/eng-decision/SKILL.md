# eng-decision · 决策记录

决策记录解决一个问题：**半年后有人问「为什么这么定」，有没有答案。**

> 模板：`../../templates/decision.md.tpl`。宿主提供插件根路径变量时优先使用。

---

## 一、什么时候该独立成文

**判据：有取舍代价的决策才独立成文。** 没有代价的只是执行细节，记一行索引即可。

| 独立成文 | 只在索引记一行 |
|---|---|
| 「放弃方案 A，代价是 X」 | 「用 Python 而非 TypeScript」（无代价） |
| 「接受某平台限制，换取 Y」 | 「字段名用 snake_case」 |
| 「推翻三个月前的结论」 | 「增加一个工具」 |
| 「决定不做某功能」 | — |

> 成文过多目录变噪声，过少关键决策无处可查。**用「有没有代价」这条线切。**

---

## 二、命名与位置

```
docs/decisions/D<N>-<slug>.md
```

- `N` 顺序号**不补零**（`D2`、`D12`）；`slug` 短横线小写英文/拼音 ≤30 字符
- 编号冲突时顺延，**禁止复用**（预检用 `eng-bootstrap` 的 `scripts/number-inventory.sh`）

### 两套编号要分清

| 形式 | 用途 |
|---|---|
| `D-1`、`D-2`… | **索引条目**（ROADMAP 决策表里的短决策） |
| `D2`、`D3`… | **独立成文的决策记录文件** |

**规则：文件用 `D<N>`，表格条目用 `D-<N>`**；架构文档用 `A<N>`、审查记录用 `R<N>`——`D` 只给决策。混用是最常见的追溯断裂来源。

**简化建议**：ROADMAP 决策索引行直接双链指向文件，文件本身是权威——不维护第二套清单。

## 三、必含六段

```markdown
## 一、背景    <触发决策的场景与约束>
## 二、选项    <候选，含被否掉的>
## 三、决定    <最终选择，一句话>
## 四、理由    <逐条>
## 五、放弃的代价    <选了它要付出什么——最容易被跳过，也最重要>
## 六、何时可能推翻  <什么条件下重新评估>
```

- **不写代价 = 宣传材料**：写了代价等于提前承认「这是已知的妥协」，被质疑时不必重新论证
- **不写推翻条件 = 决策无保质期**：条件必须可观测，如「上游把 X 改成收费 → 换 Y」「用户量超 N → 拆进程」

---

## 四、推翻时怎么处理

**不删旧文档。** 三步：

1. 旧文档 frontmatter 改 `status: superseded`
2. 旧文档顶部加指针：`> 已被 [[D<N>-xxx]] 取代。`
3. 新文档「背景」写明原方案的问题

同时 ROADMAP 决策索引把旧条目标 `🔁 已取代`——**删除会让历史双链全部悬空**。

---

## 五、反模式

| 反模式 | 后果 |
|---|---|
| 决策只存在于对话里 | 上下文一压缩就没了，新人无法追溯 |
| 只写结论不写代价 | 变成宣传；被质疑时无法自证 |
| 推翻时静默改文档 | 历史双链断裂，无法解释「为什么变了」 |
| 把愿景当决策 | 「要做最好的助理」是口号不是决策 |
| 决策记录里放实施细节 | 细节属于架构文档，混放两边都过期 |
| 编号复用 | 两条决策共用一个号，追溯彻底失效 |

## 六、与其它文档的衔接

| 文档 | 关系 |
|---|---|
| `ROADMAP.md` | 决策索引（编号唯一权威）；独立成文的决策在此双链 |
| `docs/architecture/` | 决策的**结论**落到规格；决策文档只记**过程** |
| `docs/research/` | 决策的**证据**来自调研。调研写「可引用的结论+证据」，决策写「取舍+代价」 |
| `CHANGELOG.md` | 影响用户可感知行为时记一条「变更」并引用决策编号 |

## 七、自检

```
[ ] 有「放弃的代价」且不是「几乎没有代价」
[ ] 有「何时可能推翻」且条件可观测
[ ] 编号未与既有决策冲突
[ ] 若推翻了旧决策：旧文档已标 superseded 并加指针
[ ] ROADMAP 决策索引已同步（含状态标记）
[ ] 没有把实施细节写进来
```
